# M9 — Workbench Redesign (live-first, two node domains)

- **Date:** 2026-11-06
- **Design doc:** `docs/design/M9_workbench_redesign.md` (user decisions
  recorded there: CLI untouched, wing editor = plan-view outline, 3D moves
  to Qt-native GL)
- **Driver:** user feedback that M8 shipped the right machinery with the
  wrong UX — the loop should be *build robot → build controller → run live
  → view live + recorded → tune*.

## Decisions and deviations

- **Qt3D is dead in PySide6 6.12** (Qt3DExtras ships empty; QtQuick3D is
  QML-only). The user's "switch to Qt 3D" is honoured in spirit by a
  QOpenGLWidget renderer we own — no browser, no localhost server, no
  fullscreen glitch. Documented in the design doc.
- **MeshCat is not deleted yet.** The GL path reached parity in the
  workbench (grid, wings incl. custom planforms, force arrows, live
  session, record scrub); MeshCat remains for the legacy window and CLI
  `view`/`live` until the GL renderer is confirmed on real hardware
  (offscreen GL skips in CI).
- **Recording is default-on** in the live transport (M9 design: live is
  the simulation; stop saves a standard record).
- **Wing editor is plan-view only** (user decision); twist stays in the
  kinematics profiles.

## Known gaps (honest list)

- Platform tree drag-add from the palette lands only for control blocks;
  mechanical nodes are added via the builder API / property panel for now
  (the tree editor rework is the remaining piece).
- The scope cursor does not yet scrub the GL scene (frame 0 shown on
  record open).
- GL rendering correctness is verified by construction and offscreen unit
  tests; the on-hardware visual check is the human gate.
