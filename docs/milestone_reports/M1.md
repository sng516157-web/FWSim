### Physics check of the reference run (placeholder parameters!)

Cycle-averaged per wing: F_total = [+0.0056, ±0.0053, **−0.0137**] N
(lift is −z, upward ✓; F_y antisymmetric between wings, cancels in sum ✓),
P_aero = 0.464 W per wing. Vehicle weight at the placeholder mass (15 g) is
0.147 N — total lift 0.027 N, so **the placeholder kinematics do not trim to
hover** (≈5× short). This is expected and explicitly not tuned: all vehicle
and kinematic values are `estimated` placeholders pending the Leng et al.
parameter table (action plan §6, open item 1).

Element Reynolds range in the hover run: 0.003 to 1.46×10⁴. The Dickinson
fits come from Robofly at Re ~ O(10²) — the placeholder geometry operates
outside the fit's provenance regime; recorded in the run record's validity
section and flagged here honestly.

## 3. Known failures and limitations

- **AoA sign bug found and fixed during M1:** the initial implementation used
  `atan2(−v·n, v·x)` (inverted vs the flight-dynamics convention), producing
  net downforce in the first hover run. Fixed to `α = atan2(v·n_phys, v·x̂)`;
  tests now pin the convention (LE-up + forward motion ⇒ positive α ⇒ lift up).
  This is exactly the plausible-but-wrong class brief §5.2 warns about; the
  frozen conventions in frames.md §3 ("positive θ_w increases AoA") are what
  the code now satisfies.
- Wake capture, clap-and-fling, wing deformation and any inflow model are
  excluded (A-002, A-003, A-005, A-006). The model is claimed to operate only
  in the quasi-steady regime of its coefficients' provenance, which for this
  vehicle is **unverified** (see Re note above).
- Lift direction is undefined at exactly |α| = 90° (e_L set to zero there;
  the fit's C_L(90°) ≈ 0.1 is then dropped — a documented corner, not a
  physical claim).
- MeshCat: server-side verified on Windows; browser rendering was not
  verified headlessly (open the printed URL to eyeball; full scene builder
  with per-element arrows lands with M2/M3 visualization work).
- The X-wing's aft wing pair is omitted in the M1 vehicle draft (documented
  in the YAML); two-wing assembly formalizes in M2.
- Leng et al. numerical reproduction: **PENDING** (no original data).
