Additional frozen decisions made this milestone (delegated to M0 by the stage
file, confirmed with Steven where noted):

- **Positive β** raises the anterior (+x) end of the stroke plane
  (`frames.md` §1.4).
- **Wing angles:** φ measured from +y_SP, positive = tip forward;
  θ_w = 0 = chord in stroke plane, positive = leading edge up (`frames.md` §3).
- **Left-wing mirror rule** verified numerically before freezing (pure-Python
  check, 8 random configurations, machine precision):
  `R_SP_WR_L = Rz(+φ) Rx(−ψ_w) Ry(θ_w) Rx(π)`; chord, span and the physical
  wing normal (−ẑ_BE) all mirror the right wing under `S = diag(1,−1,1)`;
  symmetric commands give `F_L = S·F_R` (`frames.md` §4).
- **Thrust direction** in the reduced model: cycle-averaged wing-force
  resultant decomposes into thrust `T ≡ F_x` along **+x_B** and lift
  `L ≡ −F_z`, applied at the wing-root midpoint (Steven's choice;
  `reduced_model_spec.md` §2).

## 3. Known failures and limitations

- No dynamics, aerodynamics, kinematics or UI code exists yet — by design
  (stage file §0.7). 39 test stubs skip with milestone-named reasons.
- Leng et al. (IMAV 2024) parameter table and suspended-test time series are
  unavailable; the reduced-model spec therefore defines its own frozen
  conventions (thrust along +x_B, geometry in §4 of the spec) and M2/M4
  data-dependent validation ships as `PENDING` (brief §12 permits this).
- The stroke-plane angle β and wing-angle conventions are self-consistent and
  frozen, but they are *our* convention — coefficients or kinematic profiles
  transcribed from papers in M1 must be converted at the boundary, with the
  conversion noted in the parameter provenance.

### Brief §10 M0 "second developer" self-check

Reading only `docs/conventions/frames.md`, `docs/conventions/notation.md` and
`docs/conventions/reduced_model_spec.md`, a second developer can determine:

- every frame's axes, origin and parent (frames.md §1, §2, §5) — including
  the left wing's anti-parallel z-axis and physical-normal rule (§4);
- every rotation order (ZYX attitude; stroke→deviation→pitch wing chain) with
  explicit 3×3 matrices (§1.3–§4, §6);
- every state of the reduced model with zero references (spec §2–§3);
- every force direction: gravity `+z_W`, lift `−z`, thrust `+x_B`, left-wing
  force mirror `F_L = S·F_R`.

**Still ambiguous / watch items (honest list):**

1. The abdomen **roll** joint axis convention is not yet pinned (M3 scope);
   only abdomen pitch is frozen (α_abd about +y_B, tip-down positive).
2. `WingSpec.hinge_location` vs. stroke-plane origin: frames.md §6 states the
   hinge location replaces the SP-origin offset, but the exact composition
   order for a body-offset hinge will be fixed with the first M1 transform
   code and finite-difference test.
3. The cycle-averaged force application point `r_T` is defined as the
   wing-root midpoint; for the X-wing reference vehicle with four wing roots,
   M2 must pick and document the precise point when the vehicle YAML lands.
